## 二、Actor 控制器与事件驱动映射

### 1. `CatActorPlayer` 核心引擎
- **Dual-Mode 播放内核**：
  - **Spritesheet Canvas 模式（生产主推）**：单画布离屏绘制（400×672 逻辑分辨率），依赖 `requestAnimationFrame` 驱动帧序，10 FPS（100ms/帧），帧级别绝对确定性，`onComplete` 回调零时延触发。
  - **Animated WebP 回退模式**：保证低端或非 Canvas 环境兼容性。
- **80ms 瞬时遮罩过渡层 (`.cat-actor-fx-layer`)**：状态切换瞬间触发 80ms 微白雾蒸汽淡化，彻底杜绝白屏与硬切接缝。
- **状态流转与事件映射表**：

| 游戏事件 | 触发条件 | Cat Actor 目标状态 | 循环规则与后置逻辑 |
| :--- | :--- | :--- | :--- |
| `ORDER_WAITING` | 开局等待 / 1.5s 无操作空闲 / 返回主菜单 | `IDLE` | 循环播放主厨呼吸与眨眼 |
| `COOK_CHOP` | 玩家按住并拖动沙拉/早餐等砧板食材 | `CHOP` | 循环播放手起刀落切菜动作 |
| `COOK_STIR` | 玩家按住并拖动拉面/热汤等锅具食材 | `STIR` | 循环播放持勺搅锅熬汤动作 |
| `ORDER_READY` | 9块拼图拼合完成出餐 (`triggerDishServeArrival`) | `PASS` | **单次播放**出餐端盘，动作完成后自动切回 `IDLE` |
| `ROUND_WIN` | 当日营业额达标 (`DAY_CLEARED`) | `WIN` | **单次播放**欢呼庆祝跳舞，结算完成切回开心 `IDLE` |

### 2. `PrinterActorPlayer` 外设控制器
- 完全独立于猫组件，仅通过游戏领域事件与小票机生命周期通信：
  - 开局自动打印第一张订单小票；
  - 监听 `session.events.on('ORDER_CREATED')`：触发 `PRINTING` 吐纸动画（1.2s），随后稳定停留在 `ORDER_OUT`。

## 三、真实游戏内实拍录屏 (MP4)

所有录屏均通过 Chrome Headless CDP 实机渲染截流，通过 FFmpeg 原生编码（H.264 / yuv420p / 25fps）：

### 1. 完整单局出餐循环实录
- **文件**：`stage4_3_runtime_full_loop.mp4` (409 KB, 10.28s)
- **验证场景**：
  1. 开局猫咪处于 `IDLE` 状态，小票机打印新订单；
  2. 玩家触控拖动拉面食材，猫咪即时切入 `COOK_STIR` 搅汤；
  3. 玩家触控拖动沙拉食材，猫咪切入 `COOK_CHOP` 切菜，连续拼装多块；
  4. 最终块吸附触发高潮完成仪式，出餐瞬间猫咪切入 `ORDER_READY` (`PASS`) 端出餐盘；
  5. 金币飘字结算，小票撕纸并打印下一单，猫咪单次端盘结束后平滑归位 `IDLE`。

### 2. 高频极限切态抗压实录
- **文件**：`stage4_3_runtime_rapid_switch.mp4` (117 KB, 5.08s)
- **验证场景**：
  - 极限序列：`IDLE` ➔ `CHOP` (250ms) ➔ `STIR` (250ms) ➔ `CHOP` (250ms) ➔ `PASS` (单次) ➔ `IDLE`。
  - **实测指标**：全程 0 处白屏、0 次抖动、0 次布局位移，80ms 蒸汽过渡平滑自然。

### 3. 当日目标达成通关实录
- **文件**：`stage4_3_runtime_win.mp4` (580 KB, 14.84s)
- **验证场景**：
  1. 连续完成订单 2 与订单 3，营业额突破 ¥200 目标达到 ¥210；
  2. `BUSINESS_GOAL_REACHED` 与 `DAY_CLEARED` 事件权威触发；
  3. 猫咪立即收到 `ROUND_WIN` 事件，展开 `WIN` 欢呼跳舞动画；
  4. 营业账本结题弹窗（"今日营业日报"、"¥210"、"100% 达成"、"大繁盛" 封印章）呈现。
